# 水质实验室 · 批次修订发布台

供水质实验室数据员使用的批次修订发布页（Flask + SQLite）。浏览器上传仪器导出的
CSV、填写批次号，系统逐行校验后预览**新增 / 修改 / 撤回（删除）**差异，确认后
**整批替换**下游采集程序读取的本地 CSV，并在网页登记当前版本与行数。

另含**平行样品质控页**：选择已发布版本并上传配对 CSV，逐对计算相对偏差，
给出最少待核查（样本号、检测项目）键集合。

## 功能与规则

- 上传 CSV 必须包含三列（表头兼容中英文）：`样本号`、`检测项目`、`浓度(mg/L)`
  （亦接受 `sample_no / analyte / concentration` 等常见别名，UTF-8、支持 BOM）。
- 逐行业务校验，错误带行号提示：
  - 同一样本同一检测项目不得重复；
  - 浓度必须是数字且 **≥ 0**（拒绝负数、空值、NaN、Inf、非数字）；
  - 样本号、检测项目不能为空，列数必须与表头一致。
- 上传内容代表修订后的**完整一批**：当前版本中存在、但本次 CSV 未包含的行，
  在预览中列为「撤回（删除）」，确认后该检测结果即被撤回。
- 预览页分类展示新增、修改（旧值→新值）、撤回、不变四类差异，确认后才发布。
- 首页登记当前版本号、批次号、行数、发布时间（UTC）与内容 SHA256，并提供
  已发布 CSV 的在线查看入口和事件日志（含每次恢复记录）。

## 平行样品质控页（`/qc`）

平行样本检测结果不一致时，实验室需要圈出**最少**的待核查（样本号、检测项目）
组合。在首页点击「进入质控页」，选择一个已发布版本并上传配对 CSV。

**配对 CSV 规则**（表头兼容中英文，UTF-8、支持 BOM）：

- 四列：`样本甲`、`样本乙`、`检测项目`、`允许相对偏差`
  （亦接受 `sample_a / sample_b / analyte / limit` 等别名）；
- 最多 **60 对**，涉及最多 **24 个**不同的（样本号、检测项目）键；
- 两样本不能相同；同项目的**无序配对不可重复**（`S1,S2,氨氮` 与 `S2,S1,氨氮` 视为重复）；
- 允许相对偏差须为**非负有限数**（拒绝负数、NaN、Inf、非数字、空值）。

**判定与核查集合**：

- 相对偏差：两浓度均为 0 时偏差记为 0，否则按 `2×|甲−乙|/(甲＋乙)` 计算；
  页面按百分比展示，偏差**严格大于**限值即判超限；
- 每个超限配对至少核查一端，构成以（样本号、检测项目）键为顶点、超限配对为边的
  **最小顶点覆盖**；
- 任一端在所选版本**缺失**时，该键**必须核查**，不能按 0 计算（强制顶点）；
- 若最少核查集合存在多个等优解，返回按键排序后**字典序最小**者
  （24 顶点内的 FPT 分支定界，结果稳定且秒级返回）。

**报告语义**：

- 逐对展示甲/乙浓度、限值、实测偏差或缺失原因，并汇总最少待核查键集合及每个键的纳入原因；
- 报告只读取**所选版本的不可变快照**并在页眉标明版本；分析期间其他页面可继续发布，
  已生成的报告不受影响（页眉同时显示当前最新版本，提示是否需要重新分析）；
- 任何无效上传都只回到表单页展示带行号的错误，**不生成报告、不产生数据变更**。

## 本地启动

环境要求：Python 3.10+（仅依赖 Flask）。

```bash
cd wq-publish
./run.sh                 # 自动创建 .venv、安装 flask，监听 http://127.0.0.1:5000
```

手动方式：

```bash
python3 -m venv --without-pip .venv   # 若系统带 ensurepip，直接 python3 -m venv .venv
# 按你的环境引导 pip 后：
.venv/bin/pip install -r requirements.txt
WQ_DATA_DIR=$PWD/data WQ_DOWNSTREAM_DIR=$PWD/downstream \
  .venv/bin/flask --app wsgi:create_app run --host 127.0.0.1 --port 5000
```

环境变量（可选）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WQ_DATA_DIR` | `./data` | SQLite 数据库、flask 密钥、隔离区存放目录 |
| `WQ_DOWNSTREAM_DIR` | `./downstream` | 下游采集程序读取目录，正式文件固定名为 `published_results.csv` |

下游采集程序只需固定读取 `WQ_DOWNSTREAM_DIR/published_results.csv`。

## Docker Compose 启动

```bash
cd wq-publish
docker compose up --build -d        # 监听 http://127.0.0.1:5000
docker compose logs -f
docker compose down                 # 数据保留在命名卷 wq-data / wq-downstream 中
```

镜像基于 `python:3.11-slim`，用单进程多线程的 waitress 提供 WSGI 服务
（`waitress-serve --call wsgi:create_app`），与 SQLite `BEGIN IMMEDIATE`
文件锁、同目录 `os.replace` 的单进程并发模型一致。SQLite 数据库、密钥、
隔离区持久化到 `wq-data` 卷，下游 CSV 持久化到 `wq-downstream` 卷；
端口默认仅绑定 `127.0.0.1`，对外暴露请自行前置反向代理。

## 操作流程

1. 打开首页，填写批次号并选择仪器导出的 CSV，点击「校验并预览增删改」。
2. 校验失败：回到首页逐条显示带行号的错误，修正后重新上传，不产生任何数据变更。
3. 校验通过：进入预览页核对新增/修改/撤回差异，可「放弃本次修订」或
   「确认无误，整批替换并发布」。
4. 发布成功后回到首页，登记版本号递增、行数更新，下游文件已原子替换。

## 数据一致性设计（如何保证要求）

**下游只会读到完整旧版或新版**

- 发布时先把新 CSV 写入下游目录内的同目录临时文件（`.tmp-publish-*.csv`），
  `flush + fsync` 后调用 `os.replace` 原子改名覆盖正式文件，并 fsync 目录。
  改名瞬间下游要么看到旧文件、要么看到完整新文件，不会读到半写内容；
  临时文件以 `.` 开头且与正式文件名不同，不会被按固定文件名读取的采集程序读到。

**文件与登记的事务关系、崩溃自动恢复**

- SQLite（`data/wq_publish.db`）是版本登记与全版本结果的唯一真相源，
  发布在 `BEGIN IMMEDIATE` 事务内完成「原子换文件 → 写新版本结果 → 更新登记表」。
- 每次启动（`Storage.recover()`）自动核对并修复：
  1. 清理崩溃遗留的 `.tmp-publish-*` 临时文件；
  2. 正式文件缺失或 SHA256 与登记不符时，以数据库登记为准原子重建；
  3. 「文件已改名但事务未提交」的现场，重启后回滚为登记中的完整版本；
  4. 下游目录中未登记的游离文件移入 `data/quarantine/` 隔离（不直接删除）；
  5. 超过 24 小时未确认的预览会话自动作废。
  所有恢复动作写入 `event_log` 并展示在首页。

**两个页面从同一版本发起修订，只允许一个成功**

- 每次预览生成带随机 token 的修订会话，记录发起时的基线版本 `base_version`。
- 确认发布时在写事务内重新比对当前版本：基线已被其他发布超越时，本会话
  标记为 `obsolete` 并返回 409 过期预览页（仍展示旧基线差异供核对），
  明确要求重新预览，绝不可能覆盖先发布者；重新预览后即可正常发布。
- 同一会话重复发布、已取消/已发布/已过期会话再次确认，一律拒绝。

## 部署提示与已知限制

- `flask run` 为开发服务器；正式环境建议用 `waitress-serve --host 127.0.0.1
  --port 5000 wsgi:create_app`（或 gunicorn 单实例多线程）。并发正确性依赖
  SQLite 的 `BEGIN IMMEDIATE` 文件锁与同目录 `os.replace`，多 worker 部署时
  必须共享同一个 `WQ_DATA_DIR` 与 `WQ_DOWNSTREAM_DIR`。
- 全量结果按版本保留在 `results` 表中，`published_versions` 表登记每个历史版本
  （批次、行数、发布时间、内容哈希），质控页可任选历史版本作为分析基线；
  暂未提供历史版本回滚的页面入口（数据具备，可后续增加），历史 CSV 文件本身只保留最新一版。
- 上传上限 16MB；认证、权限控制未包含在本版本内，建议仅监听内网或前置反向代理
  加访问控制。
